# Demonstration plan

No public demonstration video has been added yet. This document describes what a first fellowship demonstration should show.

## Planned sequence

1. State whether the input is synthetic replay or actual bench hardware.
2. Start the stream and show sensor identity, units and timing metadata.
3. Show a normal interval, then a controlled interruption or malformed synthetic packet.
4. Display missingness or uncertainty explicitly.
5. Explain what the check establishes and what remains untested.

## Acceptance evidence

- A viewer can distinguish synthetic and physical input.
- The display identifies interruptions and unavailable data.
- Records retain raw input and timestamp provenance.
- The demonstration is repeatable using documented steps.
- No BP estimate, diagnostic interpretation, or clinical reassurance is inferred from transport success.

Code, fixtures and run instructions will be added only after a deliberate review for public release. Nothing in this repository currently requires installing software or entering health information.
